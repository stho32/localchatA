# Start

## Verantwortung

Bringt das Programm vom Aufruf bis zum lauschenden Server in einen bereiten Zustand.

## Schnittstellen

- Eingehend: Kommandozeile (`Startauftrag::aus_argumenten`, rein und unit-testbar), Signale SIGTERM/Strg+C.
- Ausgehend: Ordner anlegen und sperren (`<ordner>/.localchatA.sperre`, `std::fs::File::try_lock`), [Gespräche](A00006-gespraeche.md) laden lassen, Frist-Takt starten (Tageswechsel aus der [Uhr](Aspekte/X00007-zeit.md)), Listener binden, Startzeile schreiben, Browser öffnen.

## Abhaengigkeiten

[Gespräche](A00006-gespraeche.md), [HTTP-Schnittstelle](A00004-http-schnittstelle.md), [Anwesenheit](A00010-anwesenheit.md), [Live-Kanal](A00011-live-kanal.md) — Start verdrahtet sie.

## Offene Fragen

- Start hält den Server auch bis zum geordneten Ende (`src/start/ausliefern.rs`, `src/start/verbindungen.rs`), der Verantwortungssatz beschreibt nur den Weg bis zur Bereitschaft. Empfehlung: Satz bei der nächsten Verfeinerung auf „vom Aufruf bis zum geordneten Ende“ erweitern — die Annahmeschleife bleibt im Start, weil sie Lebenszyklus (Signal, Frist) ist, nicht Übersetzung von Anfragen ([A00004](A00004-http-schnittstelle.md)). Gegenposition: Verbindungsgrenzen sind Systemgrenze und gehörten zu A00004.

## Notizen / Quellen

- Reihenfolge: Aufruf lesen → Ordner vorbereiten → Sperre → Logs laden (Index vollständig) → binden → Startzeile. Damit ist der Port erst offen, wenn der Verlauf da ist; der Health-Check ist ab der Startzeile grün.
- Erster Test (Unit): `["/tmp/x", "--port", "0", "--kein-browser"]` → `Startauftrag { ordner: "/tmp/x", port: 0, host: "0.0.0.0", browser_oeffnen: false }`; kein Provider.
- Erster Test (Integration): Binärprogramm mit Wegwerf-Ordner und `--port 0` starten, Adresse aus der Startzeile, `GET /api/gesundheit` → 200; zweiter Start auf demselben Ordner endet mit Exit 1 und nennt die Sperre.
- **Ist 2026-10-27 (nach I0001, Karte #2 Nachzug):** Reihenfolge im Code (`src/start/mod.rs`, `starten`): Aufruf lesen → Ordner vorbereiten → sperren → binden → **Signale einrichten** (Commit ccdd4b5, B0014: vor der Startzeile, damit ein Signal ab der Startzeile geordnet beendet) → Startzeile → Browser → ausliefern bis zum Signal über die eigene Annahmeschleife ([ADR-0010](../ADRs/0010-eigene-annahmeschleife-hyper-http1.md), Commit 6812820). „Logs laden“ kommt mit I0002 zwischen Sperre und Binden hinzu. Ausweichregel des Standard-Ports ist rein geprüft (B0015), kein Test bindet 7430–7479. Erster Test der Grenzen: `tests/verfuegbarkeit.rs` (Angriffsmatrix Zeilen 1–6 über das echte Programm).
- **Ergänzung 2026-10-27 (Karte #3, I0004):** (1) Die Annahmeschleife normalisiert die Gegenstelle bei `accept` einmal mit `IpAddr::to_canonical()` und setzt je Verbindung `ConnectInfo<SocketAddr>` als Request-Extension; dieselbe Adresse zählt in `Belegung::zulassen` ([ADR-0012](../ADRs/0012-identitaet-und-sitzung.md), Probe: Listener `[::]`, Anfrage über `127.0.0.1` → `127.0.0.1`). (2) Aufruf um `--erreichbar-als <name>` (mehrfach) erweitert; der Start gibt die Namen und den Rechnername (`uname().nodename()`, `rustix` Feature `system`) an den Grenzschutz ([ADR-0014](../ADRs/0014-grenzschutz-host-origin-sicherheitsheader.md)). Erster Test (Unit): `["/tmp/x", "--erreichbar-als", "chat.lan", "--erreichbar-als", "nuc"]` → `erreichbar_als: ["chat.lan", "nuc"]`; ohne Wert → Aufruffehler, Exit 2. (3) Erzeugt den Baustein [Anwesenheit](A00010-anwesenheit.md) mit Uhr und Zufall und reicht ihn über `Zustand` an den Router.
- **Ergänzung 2026-10-28 (Karte #4, I0005):** Der Start bekommt zwei Aufgaben dazu ([ADR-0016](../ADRs/0016-anwesenheitsstatus-aus-haltern-mit-nachlauf-liste-als-stand-plus-wechsel.md)): (1) ein **Ende-Signal als `watch`-Kanal**, das sowohl `ausliefern` beendet als auch jedem Ereignisstrom über den Zustand der HTTP-Schnittstelle gegeben wird — heute entsteht es erst in `ausliefern`; (2) einen **Takt-Task** (alle 250 ms `pflegen(uhr.jetzt())` an der Anwesenheit, Wechsel an den Live-Kanal), gestartet vor der Startzeile, beendet mit dem Ende-Signal. Testknöpfe: `LOCALCHATA_HERZSCHLAG_MS` (ADR-0007) kommt mit I0005; der Nachlauf (1 s) braucht keinen, Tests warten echte Sekunden oder prüfen ihn im Unit-Test mit gestellter Uhr. Erster Test: offener Strom, SIGTERM → Exit 0 in < 1 s (heute: 5 s Frist).
- **Ergänzung 2026-10-28 (Karte #5, I0006):** Die Annahmeschleife pflegt jede **zugelassene** Verbindung einmal vor dem Bedienen: `TCP_USER_TIMEOUT` = 2 × Herzschlag (nur Linux), `SO_KEEPALIVE` mit Leerlauf und Abstand = Herzschlag, 2 Proben ([ADR-0017](../ADRs/0017-stiller-abriss-kernel-erkennt-tote-verbindungen.md)). Die Pflege ist eine Naht: `ausliefern` bekommt sie als Parameter (Kernel-Fassung über `rustix::net::sockopt`, Testfassung zeichnet auf); die Werte bildet eine reine Funktion aus dem Herzschlag. Scheitert das Setzen, wird trotzdem bedient und der erste Fehler je Lauf einmal auf stderr gemeldet. Der Start reicht den Herzschlag (`LOCALCHATA_HERZSCHLAG_MS`, Standard neu 5 s) an Strom **und** Annahmeschleife.
  - **Erster Test (Unit):** `pflege_aus(5 s)` → `{10 000 ms, 5 s, 5 s, 2}`; Kernel-Pflege auf einem angenommenen Loopback-Socket → `getsockopt` liest die Werte zurück; `ausliefern` mit aufzeichnender Pflege → je zugelassener Verbindung genau ein Aufruf, abgewiesene keiner. Ersetzt: die Pflege (Naht). Mutationsprobe: Aufruf in `ausliefern` entfernen → rot.
  - Betrieb: `/api/gesundheit` nennt `herzschlag_ms` und `abrissgrenze_ms`.
- **Ergänzung 2026-10-28 (Karte #12, I0018):** (1) Nach `laden` und **vor** der Startzeile ruft der Start einmal `pflegen(heute, Start)` ([ADR-0030](../ADRs/0030-entfallen-beim-start-beim-tageswechsel-und-beim-verkuerzen-loeschen-unter-der-gespraechssperre.md)) — wer die Startzeile liest, findet keine Tage außerhalb der Frist mehr. (2) Ein zweiter Takt-Task `fristpflege::takten(gespraeche, uhr, ende, 1 s)` neben dem der Anwesenheit, gestartet vor der Startzeile, beendet mit dem Ende-Signal; er ruft `pflegen` über `spawn_blocking` nur, wenn sich das lokale Datum geändert hat. Kein neuer Testknopf: `LOCALCHATA_JETZT=…T23:59:58` lässt den Tageswechsel zwei Sekunden nach dem Start kommen. Erster Test: ADR-0030, „Folgeentscheidungen“ (Takt-Unit mit `tokio::time::pause` und gestellter Uhr; Integration über Mitternacht).
- **Ergänzung 2026-10-28 (Vorlauf „Betriebsprotokoll“):** Reihenfolge erweitert: Aufruf lesen (mit `--protokoll-stufe`/`LOCALCHATA_PROTOKOLL_STUFE`) → Uhr → … → Ordner vorbereiten → sperren → **Protokoll öffnen, Panik-Haken setzen, Protokoll bereinigen** → Bus → Verlauf laden (Ladedefekte als `WARNING laden`) → … → **Tagestakt** (Bereinigung, Episoden; später Fristpflege I0018) → Startzeile → `INFORMATION start` → … → beim Ende `INFORMATION ende`. Vor der Sperre bleiben Fehler auf stderr mit den bisherigen Exit-Codes — ein gesperrter Ordner gehört einer anderen Instanz ([ADR-0040](../ADRs/0040-betriebsprotokoll-datei-je-lokalem-tag-unter-logs-eine-zeile-je-eintrag.md) Regel 1). Hintergrundaufgaben (Takt, Tagestakt) laufen über `bewacht(…)` ([ADR-0042](../ADRs/0042-stufen-ereigniskatalog-episoden-und-tagesgrenze-des-betriebsprotokolls.md) Regel 4); die Verbindungsabweisung der Annahmeschleife wird eine Warning-Episode je Herkunft (heute still).
- **Ergänzung 2026-10-28 (Abgleich I0018 ↔ Tagestakt, vor Karte #24):** Ersetzt Punkt (2) der Ergänzung „Karte #12, I0018“: es gibt keinen Task `fristpflege::takten`; die Fristpflege ist die zweite Tagesaufgabe des **einen** Tagestakts ([ADR-0041](../ADRs/0041-betriebsprotokoll-als-eigenes-modul-rotation-beim-schreiben-bereinigung-14-tage.md), Ergänzung „Vertrag des Tagestakts“). Reihenfolge: … → Protokoll öffnen → Panik-Haken → Bereinigung (Start, Datum b) → Laden → Fristpflege (Start, Datum p) → Binden → Ende-Signal → Anwesenheits-Takt und Tagestakt (beide bewacht; Tagesaufgaben `bereinigen` mit `zuletzt = b`, `fristpflege` mit `zuletzt = p`; Sekundenaufgabe `episoden`) → Startzeile → `INFORMATION start`. Der Start übergibt jeder Tagesaufgabe das Datum, das ihr Start-Lauf bekam; der Takt läuft eine Aufgabe nur bei `heute ≠ zuletzt` und setzt `zuletzt` vor dem Aufruf. Eine Panik in einer Tagesaufgabe beendet den Takt nicht (ERROR, Wiederholung beim nächsten Wechsel); eine Panik in der Sekundenaufgabe meldet nur diese ab (`aufgaben_ausgefallen`). Ist: Code hat nur den Anwesenheits-Takt (`src/start/mod.rs:114–121`); Tagestakt, Bereinigung und Fristpflege sind Soll (F0052, F0035).
- **Ergänzung 2026-10-28 (R00015, F0056):** Die Annahmeschleife nimmt je Gegenstelle **160** Verbindungen an (statt 64), gesamt unverändert `min(512, Deskriptoren / 2)`; Herleitung aus dem Lastprofil im Kommentar von `JE_GEGENSTELLE` ([ADR-0010](../ADRs/0010-eigene-annahmeschleife-hyper-http1.md), Ergänzung R00015). Soll ab F0056, Ist bis dahin 64.

- **Ergänzung 2026-10-29 (Karte #35, Soll):** Die Annahmeschleife setzt je Verbindung neben `ConnectInfo` (Gegenstelle) die **lokale Adresse** der Verbindung, kanonisch wie die Gegenstelle, als Request-Extension — der Grenzschutz löst sie rückwärts auf und nennt sie in der Abweisungsseite ([ADR-0045](../ADRs/0045-host-namen-des-eigenen-netzes-automatisch-oeffentliche-nur-ausdruecklich.md)). Der Start erzeugt die Namensauskunft (echt; im Debug-Build ersetzt durch `LOCALCHATA_TESTNAMEN`, falscher Wert Exit 2) und reicht sie mit Rechnername und `--erreichbar-als` an den Grenzschutz. Erster Test (Integration, echtes Programm über `127.0.0.1`): eine Route hinter dem Grenzschutz sieht als lokale Adresse `127.0.0.1`; über `[::1]` (bei `--host ::`) `::1`.
- **Ergänzung 2026-10-29 (Karte #35, Entscheidung des Betreibers):** Aufruf um `--alle-namen` (Umgebung `LOCALCHATA_ALLE_NAMEN=1`, falscher Wert Exit 2, sofern der Schalter nicht im Aufruf steht — Abgleich mit ADR-0043 Karte #26) erweitert; der Start schreibt dann vor der Startzeile ein WARNING mit dem Rebinding-Risiko ins Betriebsprotokoll ([ADR-0045](../ADRs/0045-host-namen-des-eigenen-netzes-automatisch-oeffentliche-nur-ausdruecklich.md) Regel 9). Erster Test (Unit): `["/tmp/x", "--alle-namen"]` → `alle_namen: true`; ohne → `false`.
- **Ergänzung 2026-10-29 (Karte #35, Angriffsmatrix des `security-reviewer`):** `--alle-namen` neben einem ungültigen `LOCALCHATA_ALLE_NAMEN` folgt der einheitlichen Regel in ADR-0043 (Ergänzung Karte #26, entschieden: steht der Schalter im Aufruf, ist er an und die Umgebung wird nicht gelesen) — [ADR-0045](../ADRs/0045-host-namen-des-eigenen-netzes-automatisch-oeffentliche-nur-ausdruecklich.md), Ergänzung E7 und „Abgleich mit ADR-0043, Karte #26“. Erster Test (Integration): `--alle-namen` + `LOCALCHATA_ALLE_NAMEN=ja` → Start mit `alle_namen: true`.
- **Ergänzung 2026-10-29 (Karte #35 Nacharbeit, Soll):** Das Prozessende gehört zum Start: auf Unix endet `main` (`src/main.rs`) nach `block_on(ausfuehren(…))`, `drop(laufzeit)` und dem Leeren von stdout/stderr mit `_exit(code)` — `exit()` der glibc wartete sonst auf einen Faden in `getaddrinfo` (SIGTERM während `gibtsnicht.local`: 4,0 s). `start::ausfuehren` liefert dafür den Exit-Code als Zahl (`u8`); `libc` wird direkte Abhängigkeit (nur Unix), `unsafe` gibt es genau einmal in `src/main.rs`, die Bibliothek bleibt `#![forbid(unsafe_code)]` ([ADR-0010](../ADRs/0010-eigene-annahmeschleife-hyper-http1.md), Ergänzung „Prozessende ohne das Aufräumen der C-Bibliothek“). Ist: `main` kehrt zurück (`src/main.rs:6–14`).
