# User Stories — R00029 Anhänge über die API ablegen, senden und ausliefern

Für jedes Szenario gilt, wenn nicht anders genannt: Start mit `TZ=Europe/Berlin localchatA <ordner> --port 0 --host 127.0.0.1 --kein-browser --plattenquote 10MiB` auf einem Wegwerf-Ordner mit dem leeren Ordner `channels/allgemein/`; `<p>` ist der Port aus der Startzeile. Beitritte per `curl` wie in den User Stories zu R00011; `S(<name>)` ist der Sitzungs-Header. Die drei Aufrufe eines Agenten — `<token>`, `<n>`, `<id>` einsetzen:

```
curl -s -X POST -H 'X-LocalchatA-Sitzung: <token>' -H 'Content-Type: application/json' \
  -d '{"name":"bericht.pdf","bytes":<n>}' http://127.0.0.1:<p>/api/anhaenge
curl -s -X PUT -H 'X-LocalchatA-Sitzung: <token>' -H 'Content-Type: application/octet-stream' \
  --data-binary @bericht.pdf http://127.0.0.1:<p>/api/anhaenge/<id>
curl -s -X POST -H 'X-LocalchatA-Sitzung: <token>' -H 'Content-Type: application/json' \
  -d '{"text":"Bericht anbei","anhaenge":["<id>"]}' http://127.0.0.1:<p>/api/channels/allgemein/nachrichten
```

Quote 10 MiB heißt: 1 MiB bleibt dem Text, für Anhänge sind 9 MiB (9.437.184 Bytes) da. Testdateien legt der Prüfer im Wegwerf-Ordner an (z. B. `head -c 2457600 /dev/urandom > bericht.pdf`, Bilder und Videos mit `ffmpeg` bzw. einem kleinen Skript).

## F0097 Anmelden und Hochladen über die API

Rolle: **Agent `beta` in einer KI-Session** (Shell mit `curl`), der dem Team einen Bericht als Datei geben soll.

Als Agent möchte ich eine Datei anmelden und hochladen und vorher erfahren, ob Platz ist, damit ich nicht Megabytes schicke, die dann abgewiesen werden.

### US-1: Anmelden und hochladen

- **Gegeben** `beta` ist per `curl` beigetreten, `bericht.pdf` hat 2.457.600 Bytes
- **Wenn** `beta` die Datei mit 2.457.600 Bytes anmeldet
- **Dann** antwortet die Instanz 201 mit einer `id` aus 26 Zeichen, `hochladen` und `anlauf_bis` etwa eine Minute nach jetzt
- **Und** `/api/gesundheit` zeigt `reserviert` 2.457.600 und `hochladungen` 1
- **Wenn** `beta` die Datei hochlädt
- **Dann** antwortet die Instanz 200 mit `gueltig_bis` etwa 15 Minuten nach jetzt

### US-2: Kein Platz — Antwort vor dem ersten Byte

- **Gegeben** `beta` hat 9.437.184 Bytes angemeldet (der ganze Platz für Anhänge)
- **Wenn** `beta` eine weitere Datei mit 1 Byte anmeldet
- **Dann** antwortet die Instanz 507 mit `regel: "quote"`, `frei_fuer_anhaenge: 0` und dem Text „Nicht hochgeladen: der Platz für Anhänge ist voll — noch 0,0 MiB frei; Text kann weiter gesendet werden.“ (Größe nach ADR-0044 Regel 4: unter 1 GiB in MiB, eine Nachkommastelle)
- **Wenn** `beta` den Text `Platz für Anhänge ist voll` sendet
- **Dann** antwortet die Instanz 201 — Text geht weiter
- **Wenn** `beta` die erste Anmeldung mit `DELETE` verwirft
- **Dann** antwortet die Instanz 204, und `/api/gesundheit` zeigt `reserviert` 0

### US-3: Falscher Name

- **Gegeben** `beta` ist beigetreten
- **Wenn** `beta` eine Datei mit dem Namen `../passwd` anmeldet
- **Dann** antwortet die Instanz 422 mit `regel: "name"` und einem Grund; nichts ist reserviert
- **Wenn** `beta` `Bericht März.pdf` anmeldet
- **Dann** antwortet die Instanz 201 mit `name: "Bericht März.pdf"`

### US-4: Abgebrochenes Hochladen und Erneut

- **Gegeben** `beta` hat 2.457.600 Bytes angemeldet
- **Wenn** `beta` das Hochladen nach etwa 1 MiB abbricht (`curl` mit `--limit-rate 200k` und Strg+C)
- **Dann** liegt im Ordner `.eingang/` keine `.teil`-Datei, die Reservierung bleibt
- **Wenn** `beta` innerhalb einer Minute denselben `PUT` erneut ganz sendet
- **Dann** antwortet die Instanz 200

### US-5: Falsche Länge

- **Gegeben** `beta` hat 2.457.600 Bytes angemeldet
- **Wenn** `beta` eine Datei mit 2.457.599 Bytes hochlädt
- **Dann** antwortet die Instanz sofort 422 mit `regel: "laenge"` und `erwartet: 2457600`, ohne die Bytes zu lesen

### US-6: Vergessene Anmeldung räumt sich weg

- **Gegeben** `beta` hat 1 Byte angemeldet und lädt nichts hoch
- **Wenn** zwei Minuten vergehen
- **Dann** zeigt `/api/gesundheit` `reserviert` 0 und `hochladungen` 0

Rolle: **Betreiberin `shoff`**, die die Instanz betreibt.

Als Betreiberin möchte ich, dass ein Neustart nichts Halbes zurücklässt, damit der Ordner nicht mit Resten vollläuft.

### US-7: Neustart leert den Eingang

- **Gegeben** `beta` hat eine Datei hochgeladen, aber nicht gesendet
- **Wenn** die Betreiberin die Instanz beendet und neu startet
- **Dann** ist `.eingang/` leer, `/api/gesundheit` zeigt `reserviert` 0

## F0098 Art der Datei erkennen

Rolle: **Agent `beta`**, der wissen will, wie die anderen seine Datei sehen werden.

Als Agent möchte ich in der Antwort sehen, als was die Instanz meine Datei erkannt hat, damit ich weiß, ob sie als Bild, Video oder nur zum Laden erscheint.

### US-8: Bild mit Maßen

- **Gegeben** `beta` hat `bildschirm.png` (1280 × 800) angemeldet
- **Wenn** `beta` sie hochlädt
- **Dann** nennt die 200 `art: "image/png"`, `breite: 1280`, `hoehe: 800`

### US-9: Die Endung täuscht nicht

- **Gegeben** `beta` hat eine HTML-Datei unter dem Namen `bild.png` angemeldet
- **Wenn** `beta` sie hochlädt
- **Dann** nennt die 200 `art: "text/plain; charset=utf-8"`, `breite: null`, `hoehe: null`

### US-10: Unbekanntes wird Datei zum Laden

- **Gegeben** `beta` hat `archiv.zip` angemeldet
- **Wenn** `beta` sie hochlädt
- **Dann** nennt die 200 `art: "application/octet-stream"`

## F0099 Senden mit Anhängen

Rolle: **Agent `beta`**, der dem Channel einen Bericht mit Belegen schickt; **Agent `alpha`** liest mit.

Als Agent möchte ich eine Nachricht mit Dateien senden, auch ohne Text, damit die anderen Bericht und Belege an einem Ort finden.

### US-11: Nachricht mit Anhang

- **Gegeben** `beta` hat `bericht.pdf` hochgeladen; `alpha` liest den Strom
- **Wenn** `beta` `Bericht anbei` mit der ID sendet
- **Dann** antwortet die Instanz 201; die Nachricht trägt `anhaenge` mit `name: "bericht.pdf"`, `bytes: 2457600`, `url: "/anhaenge/<id>"`
- **Und** `alpha` sieht im Strom dieselbe Liste
- **Und** die Datei liegt unter `channels/allgemein/anhaenge/<heute>/`, lesbar benannt, der Eingang ist leer

### US-12: Nur Dateien, kein Text

- **Gegeben** `beta` hat zwei Bilder hochgeladen
- **Wenn** `beta` `{"text":"","anhaenge":[<id1>,<id2>]}` sendet
- **Dann** antwortet die Instanz 201 mit `text: ""` und zwei Anhängen in dieser Reihenfolge
- **Wenn** `beta` `{"text":""}` ohne Anhänge sendet
- **Dann** antwortet die Instanz 422 mit `regel: "leer"`

### US-13: Dieselbe Datei kein zweites Mal

- **Gegeben** `beta` hat eine Nachricht mit Anhang `<id>` gesendet
- **Wenn** `beta` eine zweite Nachricht mit derselben `<id>` sendet
- **Dann** antwortet die Instanz 422 mit `regel: "anhang"`, `grund: "unbekannt"`

### US-14: Fremde Datei nicht senden

- **Gegeben** `gamma` hat eine Datei hochgeladen und ihre ID verraten
- **Wenn** `beta` eine Nachricht mit dieser ID sendet
- **Dann** antwortet die Instanz 422 mit `grund: "fremd"`; `gamma` kann die Datei danach selbst senden

### US-15: Nach dem Neustart noch da, nach der Frist weg

- **Gegeben** `beta` hat eine Nachricht mit Anhang gesendet
- **Wenn** die Instanz neu startet
- **Dann** liefert der Verlauf dieselbe Nachricht mit demselben Anhang
- **Wenn** die Instanz mit `LOCALCHATA_JETZT` acht Tage später neu startet (Frist 7)
- **Dann** sind Tagesdatei und `anhaenge/<tag>/` weg, und `/api/gesundheit` zählt sie nicht mehr in `belegt`

## F0100 Ausliefern mit Art und Teilabruf

Rolle: **Agent `alpha`** auf einem anderen Rechner, der die Datei aus der Nachricht holt.

Als Agent möchte ich eine Datei aus einer Nachricht mit einem einfachen `curl` holen und große Downloads fortsetzen können, damit ich nicht von vorn beginne.

### US-16: Laden mit dem Link

- **Gegeben** `beta` hat `bericht.pdf` an eine Nachricht gehängt; `alpha` kennt die `url` aus dem Verlauf
- **Wenn** `alpha` `curl -OJ http://127.0.0.1:<p>/anhaenge/<id>` aufruft, ohne Sitzung
- **Dann** liegt `bericht.pdf` byte-gleich bei `alpha`
- **Und** die Antwort trägt `Content-Security-Policy: sandbox; default-src 'none'`

### US-17: Fortsetzen

- **Gegeben** `alpha` hat die ersten 1.000.000 Bytes einer 2.457.600-Byte-Datei
- **Wenn** `alpha` mit `curl -C - -o teil.pdf …/anhaenge/<id>` fortsetzt
- **Dann** antwortet die Instanz 206 mit `Content-Range: bytes 1000000-2457599/2457600`, und die Datei ist danach vollständig

### US-18: Unbekannter Link

- **Gegeben** die Instanz läuft
- **Wenn** jemand `/anhaenge/aaaaaaaaaaaaaaaaaaaaaaaaaa` aufruft
- **Dann** antwortet die Instanz 404 mit „Diesen Anhang gibt es nicht (mehr).“

Rolle: **Teilnehmerin `anna`** im Browser, die einen Anhang von jemand anderem öffnet.

Als Teilnehmerin möchte ich jeden Anhang öffnen können, ohne dass er etwas in meinem Namen tut, damit eine präparierte Datei mir nicht schadet.

### US-19: Präpariertes HTML stiehlt nichts

- **Gegeben** `anna` ist im Browser beigetreten; `beta` hat `boese.html` mit einem Skript, das das Token aus `localStorage` liest, an eine Nachricht gehängt
- **Wenn** `anna` den Link `/anhaenge/<id>` im Browser öffnet
- **Dann** zeigt der Browser den Quelltext der Datei, kein Skript läuft, und `anna` bleibt beigetreten

## F0103 Anhänge im Betrieb

Rolle: **Betreiberin `shoff`**, die im Betriebsprotokoll nachsieht, was los war.

Als Betreiberin möchte ich große Übertragungen und Abweisungen im Protokoll sehen, aber nie die Links, damit ich den Betrieb beurteilen kann, ohne Zugriff auf fremde Dateien zu verraten.

### US-20: Großes Hochladen im Protokoll

- **Gegeben** die Instanz läuft mit Standard-Stufe
- **Wenn** `beta` eine Datei mit 100 MiB hochlädt
- **Dann** steht in `logs/<heute>.log` eine Zeile `INFORMATION anhang Großes Hochladen abgeschlossen` mit Bytes, Dauer und MiB/s
- **Und** weder die Anhang-ID noch der Name der Datei steht irgendwo in `logs/`

### US-21: Volle Anhänge im Protokoll

- **Gegeben** der Platz für Anhänge ist voll
- **Wenn** `beta` dreimal eine Datei anmeldet
- **Dann** steht genau eine Episode `WARNING quote Anhänge abgewiesen: Platz für Anhänge voll` mit `kennung=beta@127.0.0.1`

### US-22: Chat bleibt flüssig, während hochgeladen wird (Messwert)

- **Gegeben** die Instanz läuft im Release-Build auf dem Zielrechner; zwei Rechner im LAN laden gleichzeitig je 1 GiB hoch
- **Wenn** ein dritter Rechner fünf Textnachrichten je Sekunde sendet und ein Browser mitliest
- **Dann** erscheint jede Nachricht im Browser in unter 1 s, und die Antwortzeiten bleiben in den Grenzen aus R00029 (Gesundheit p90 ≤ 0,15 s, Senden p90 ≤ 0,25 s)
