# User Stories — R00024 Instanz über ihren Netznamen öffnen

Für jedes Szenario gilt, wenn nicht anders genannt:

- Start mit `localchatA <ordner> --port 0 --host 127.0.0.1 --kein-browser` auf einem frischen Ordner, `TZ=Europe/Berlin`, im Debug-Build (`cargo run`).
- `<p>` ist der Port aus der Startzeile, `heute.log` die Datei `logs/<lokales Datum>.log`.
- „Testnamen“ heißt `LOCALCHATA_TESTNAMEN='127.0.0.1>nuc5.fritz.box;chat.local=127.0.0.1;drucker.local=192.0.2.1;boese.example=127.0.0.1'`.
- „Testbrowser“ heißt Chromium, gestartet mit `--host-resolver-rules="MAP nuc5.fritz.box 127.0.0.1, MAP chat.local 127.0.0.1, MAP drucker.local 127.0.0.1, MAP boese.example 127.0.0.1"`. Der Browser findet die Namen so ohne DNS; welchen Namen die Instanz annimmt, entscheiden die Testnamen.

## F0077 Über den Rückwärtsnamen öffnen

### Rolle: Betreiber der Instanz im Heimnetz hinter einer Fritz!Box

Als Betreiber möchte ich die Instanz unter dem Namen öffnen, den der Router meinem Rechner gibt, damit ich und das Team keine IP-Adresse abtippen und ich nichts beim Start einstellen muss.

#### US-1: Der Router-Name öffnet die Instanz

- **Gegeben** die Instanz läuft auf dem Rechner des Betreibers mit `localchatA <ordner> --kein-browser` (Release-Build, ohne `--erreichbar-als`, ohne Testnamen), und `getent hosts <lan-ip>` liefert für die LAN-Adresse des Rechners den Namen `nuc5.fritz.box`
- **Wenn** der Betreiber im Browser eines Rechners im selben Netz `http://nuc5.fritz.box:<p>/` öffnet
- **Dann** erscheint die Oberfläche von localchatA mit dem Bildschirm zum Beitreten, und die Adresszeile zeigt weiter `nuc5.fritz.box`
- **Und** `heute.log` enthält genau eine Zeile `INFORMATION grenzschutz Host-Name über Rückwärtsauflösung erlaubt` mit `name=nuc5.fritz.box` und der LAN-Adresse als `adresse=`

#### US-2: Derselbe Weg im Testaufbau

- **Gegeben** die Instanz läuft mit den Testnamen
- **Wenn** der Entwickler im Testbrowser `http://nuc5.fritz.box:<p>/` öffnet, danach `http://NUC5.Fritz.Box:<p>/`
- **Dann** erscheint beide Male die Oberfläche mit dem Titel `localchatA`
- **Und** `heute.log` enthält die Zeile „Host-Name über Rückwärtsauflösung erlaubt“ mit `name=nuc5.fritz.box` genau einmal

#### US-3: Ein öffentlicher Name bleibt zu, auch wenn er auf die Instanz zeigt

- **Gegeben** die Instanz läuft mit den Testnamen; `boese.example` zeigt dort auf `127.0.0.1`, also auf die Instanz
- **Wenn** ein Skript `curl -s -o /dev/null -w '%{http_code}' -H 'Host: boese.example:<p>' http://127.0.0.1:<p>/api/gesundheit` ausführt
- **Dann** antwortet die Instanz 403
- **Und** `heute.log` enthält keine Zeile „Host-Name über … erlaubt“ mit `name=boese.example`

## F0078 Name im lokalen Namensraum

### Rolle: Teilnehmerin im Büronetz, die den mDNS-Namen `chat.local` kennt

Als Teilnehmerin möchte ich die Instanz unter dem kurzen Namen öffnen, den jemand im Netz für sie eingerichtet hat, damit ich mir keine Adresse merken muss.

#### US-4: Ein `.local`-Name auf die Instanz öffnet sie

- **Gegeben** die Instanz läuft mit den Testnamen
- **Wenn** die Teilnehmerin im Testbrowser `http://chat.local:<p>/` öffnet
- **Dann** erscheint die Oberfläche mit dem Titel `localchatA`
- **Und** `heute.log` enthält eine Zeile `INFORMATION grenzschutz Host-Name über lokalen Namensraum erlaubt` mit `name=chat.local` und `adresse=127.0.0.1`

#### US-5: Ein `.local`-Name auf einen anderen Rechner öffnet sie nicht

- **Gegeben** die Instanz läuft mit den Testnamen; `drucker.local` zeigt dort auf `192.0.2.1`, eine Adresse, die nicht dem Rechner der Instanz gehört
- **Wenn** die Teilnehmerin im Testbrowser `http://drucker.local:<p>/` öffnet
- **Dann** sieht sie die Seite „Diese Adresse ist für localchatA nicht freigegeben“ (ab F0079; vorher den Text der 403)

## F0079 Abweisung als verständliche Seite

### Rolle: Teilnehmer im Browser, der einen Link mit einem fremden Namen bekommen hat

Als Teilnehmer möchte ich verstehen, warum die Seite nicht aufgeht, und mit einem Klick zur Instanz kommen, damit ich nicht den Betreiber fragen muss.

#### US-6: Ein öffentlicher Name ergibt eine deutsche Seite mit Link

- **Gegeben** die Instanz läuft mit den Testnamen
- **Wenn** der Teilnehmer im Testbrowser `http://boese.example:<p>/` öffnet
- **Dann** sieht er die Überschrift „Diese Adresse ist für localchatA nicht freigegeben“, einen Link `http://127.0.0.1:<p>/`, den Satz „Der Betreiber kann den Namen boese.example mit `--erreichbar-als boese.example` beim Start freigeben.“ und einen Satz, warum (fremde Websites)
- **Und** die Seite ist deutsch, ohne Stil und ohne Skript
- **Und** in der Konsole stehen höchstens die Meldungen „Failed to load resource“ zu den 403 auf die Seite und auf `/favicon.ico`

#### US-7: Der Link führt zur Instanz

- **Gegeben** der Teilnehmer sieht die Seite aus US-6
- **Wenn** er auf den Link klickt
- **Dann** öffnet sich `http://127.0.0.1:<p>/` mit der Oberfläche von localchatA

### Rolle: Agent, der die API mit einem falschen Namen anspricht

Als Agent möchte ich eine Fehlermeldung als Text mit der richtigen Adresse bekommen, damit ich oder mein Mensch den Aufruf korrigieren kann.

#### US-8: Der Agent bekommt Text mit der Adresse

- **Gegeben** die Instanz läuft mit den Testnamen
- **Wenn** der Agent `curl -s -i -H 'Host: boese.example:<p>' -H 'Accept: application/json' http://127.0.0.1:<p>/api/gesundheit` ausführt
- **Dann** antwortet die Instanz 403 mit `Content-Type: text/plain; charset=utf-8`
- **Und** der Text enthält `boese.example`, `http://127.0.0.1:<p>/`, `--erreichbar-als boese.example` und „Namen des eigenen Netzes gelten automatisch“
- **Und** die Antwort enthält kein `<html`

## F0080 Schalter `--alle-namen`

### Rolle: Betreiber, der die Instanz bewusst unter einem öffentlichen Firmennamen betreibt

Als Betreiber möchte ich ausnahmsweise jeden Namen zulassen und dabei sehen, welches Risiko ich eingehe, damit ich die Entscheidung bewusst treffe und sie später nachvollziehen kann.

#### US-9: Mit `--alle-namen` öffnet jeder Name, und die Instanz warnt

- **Gegeben** ein frischer Ordner
- **Wenn** der Betreiber die Instanz mit `--alle-namen` startet und danach im Testbrowser `http://boese.example:<p>/` öffnet
- **Dann** steht vor der Startzeile auf stderr eine `WARNING grenzschutz`-Zeile, die mit „--alle-namen ist aktiv: jeder Host-Name wird angenommen“ beginnt und DNS-Rebinding nennt; dieselbe Zeile steht in `heute.log`
- **Und** im Browser erscheint die Oberfläche von localchatA
- **Und** `curl -s http://127.0.0.1:<p>/api/gesundheit` meldet `"alle_namen":true`

#### US-10: Eine fremde Website ohne umgebogenen Namen bleibt trotzdem draußen

- **Gegeben** die Instanz läuft mit `--alle-namen`
- **Wenn** ein Skript `POST /api/beitreten` mit `{"name":"beta"}`, `Content-Type: application/json`, `Host: 127.0.0.1:<p>` und `Origin: http://andere.example` schickt
- **Dann** antwortet die Instanz 403, und `beta` ist nicht beigetreten (`GET /api/teilnehmer` mit einer eigenen Sitzung zeigt keinen `beta`)

#### US-11: Ein falscher Wert verhindert den Start

- **Gegeben** ein frischer Ordner
- **Wenn** der Betreiber `LOCALCHATA_ALLE_NAMEN=ja localchatA <ordner> --kein-browser` startet
- **Dann** endet das Programm mit Exit 2, und eine Zeile auf stderr nennt `LOCALCHATA_ALLE_NAMEN`
- **Und** ohne den Schalter meldet `/api/gesundheit` `"alle_namen":false`
